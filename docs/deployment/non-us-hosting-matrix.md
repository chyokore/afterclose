## Region and runtime evidence

- **Netlify:** [function configuration](https://docs.netlify.com/build/functions/configuration/) restricts regional selection to Pro/Enterprise. Free cannot acquire a compliant region by adding source configuration. [Pricing](https://www.netlify.com/pricing/) covers Free credits. Existing package success cannot cure US execution.
- **Workers:** [limits](https://developers.cloudflare.com/workers/platform/limits/) specify 10 ms Free CPU. [Placement](https://developers.cloudflare.com/workers/configuration/placement/) optimizes proximity; a cloud-region hint is not a country guarantee. [Regional Services for Workers](https://developers.cloudflare.com/data-localization/how-to/workers/) explicitly excludes outgoing subrequests. No Free compliant egress guarantee established. The new [benchmark](gateway-cpu-benchmark.md), not the old full-Next benchmark, fails the conservative CPU-fit gate independently.
- **Deno:** [migration guide](https://docs.deno.com/deploy/migration_guide/) describes `us`, `eu`, and `global`; an EU label is insufficient because Netherlands is prohibited. [Getting started](https://docs.deno.com/deploy/getting_started/) supports region and secret configuration. [Runtime](https://docs.deno.com/deploy/reference/runtime/) and [pricing](https://deno.com/deploy/pricing) describe the new platform. [Changelog](https://docs.deno.com/deploy/changelog/) distinguishes restricted unverified Free from verified allowance and Free pause from Pro overages. Do not reuse Deploy Classic's historical region map.
- **Supabase:** [regional invocation](https://supabase.com/docs/guides/functions/regional-invocation) supports Frankfurt through `x-region` or `forceFunctionRegion`; exposes `SB_REGION` and `x-sb-edge-region`. Explicit header selection does not automatically fail over. This is per-request routing, not a deployment-wide lock. Require a fail-closed trusted-runtime guard before any outbound provider work. [Egress guidance](https://supabase.com/docs/guides/troubleshooting/why-supabase-edge-functions-cannot-provide-static-egress-ips-for-whitelisting-3d78b0) says addresses are dynamic, not stable allowlist ranges; it does not guarantee country retention. Regional egress is an inference requiring confirmation, not PASS. No proxy/static-IP purchase is proposed. [Secrets](https://supabase.com/docs/guides/functions/secrets), [dependencies](https://supabase.com/docs/guides/functions/dependencies), and [limits](https://supabase.com/docs/guides/functions/limits) support the proposed adapter, subject to execution tests.
- **Vercel:** [function regions](https://vercel.com/docs/functions/configuring-functions/region) allow one selected Hobby region. Use `regions: ["fra1"]`, never default US `iad1`; [region directory](https://vercel.com/docs/regions) identifies Frankfurt. [Node versions](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions) supports 24. [Hobby](https://vercel.com/docs/plans/hobby) documents quotas; [fair use](https://vercel.com/docs/limits/fair-use-guidelines) restricts it to personal noncommercial use. Prize/competition eligibility is not assumed: obtain provider clarification if financial-gain terms are ambiguous. [Environment secrets](https://vercel.com/docs/environment-variables/sensitive-environment-variables) are server-side. [Outbound IP guidance](https://vercel.com/kb/guide/how-to-allowlist-deployment-ip-address) does not establish a free static-IP solution; regional dynamic egress needs proof.
- **Render:** [regions](https://render.com/docs/regions) offers Frankfurt and Singapore; [outbound addresses](https://render.com/docs/outbound-ip-addresses) are region-dependent. [Free services](https://render.com/docs/free), [FAQ](https://render.com/docs/faq), and [bandwidth](https://render.com/docs/outbound-bandwidth) establish the sleep, quota and payment-method distinctions. No new account/workspace workaround is recommended.
- **Fly:** [current trial](https://fly.io/docs/about/free-trial/) is too short to establish a durable zero-cost backend. Research stopped at this mandatory failure. No additional providers added.

## Finalist performance and compatibility

Supabase needs a `Deno.serve` entry point, explicit Node compatibility/import checks, route normalization, and the region guard. Vercel needs a Node HTTP-to-Fetch adapter and Frankfurt configuration. These are estimated SMALL ADAPTER tasks, not implemented or verified ports. A runtime incompatibility requiring canonical changes eliminates that candidate instead of authorizing a rewrite.

Both retain the canonical engine, receipt schema/digest, fail-closed unavailable states, per-instance cache/rate limits, and exact production CORS origin `https://afterclose-preview.pages.dev`. No browser API keys or wildcard CORS. Public read-only access does not imply unlimited provider calls; existing per-instance throttling is not a global abuse quota.

Historical local genuine-request wall time was median 1.102 s, p90/max 3.464 s with about 12.7 KB responses. A seconds-scale uncached experience is a planning expectation only; neither finalist has hosted latency measurements. Cold starts and Frankfurt-to-Binance routing may increase it. At 12.7 KB, 5 GB would hold roughly 390k response bodies, before headers/other traffic and shared usage; 500k invocation allowance is not a promise of 500k usable observations.

Supabase [pauses low-activity Free projects](https://supabase.com/docs/guides/platform/free-project-pausing) based on database activity over seven days; gateway traffic alone must not be assumed sufficient. Owner must inspect pause warnings/dashboard through judging and resume if needed. No artificial keepalive/database feature is proposed. If the judging window requires unattended continuous availability that Free cannot provide, reject it. Vercel is a fallback only after its separate eligibility gate passes.

Architecture remains: existing Cloudflare Pages → regional gateway → Binance → unchanged Reference Truth Engine → unchanged Evidence Receipt. Leave Netlify inactive temporarily for diagnostic retention; never point the judging frontend at it. Disabling/deleting it requires a separate action and was not performed.
